= Hypatia — EXPLAINME
:toc: preamble

This file backs each README claim with a code path and an honest caveat; read
it after the README if you want to know what is real.

Counts were taken from the tree on 2026-11-09 with the command shown.
Volatile figures (repositories, outcomes, dispatches) are not quoted; generate

== Claim-to-implementation map

=== Symbolic rules, distilled from learning

[quote, README.adoc]
____
*Symbolic reasoning* — Elixir rules producing fast, deterministic findings, in
42 source files under `lib/rules/`
____

[quote, README.adoc]
____
That loop is the design, not yet the running code. Today the rules are hand-written, and the
neural layer can only lower a recipe's confidence or demote a finding.
____

How this is implemented::
Pure-Elixir modules in link:lib/rules/[] behind `Hypatia.Rules`
(link:lib/rules/rules.ex[]). The escript runs them with no OTP tree and no
neural process (`app: nil` in link:mix.exs[]). The count is
`find lib/rules -maxdepth 1 -name '*.ex' | wc -l`. link:scripts/check-readme-claims.sh[]
measures it, with the README's other structural counts, in the Validate Documentation
job, and fails on drift.

Caveat::
The generated link:docs/rules/catalogue.adoc[] says 41 and lacks
`structured_format`. No code path distils learned patterns into rules:
`learn_from_fix/3` and `promote_patterns/0` in link:lib/rules/learning.ex[]
have no outside callers, and `git grep RecipeGenerator` finds no caller.
The README states this beside the design sentence.

=== Neural learning

[quote, README.adoc]
____
*Neural learning* — 8 networks on a shared blackboard, learning which fixes actually stick
____

How this is implemented::
Eight networks in link:lib/neural/[] (trust graph, mixture of experts,
liquid state machine, echo state, radial basis, GNN, VAE, sequence model)
run in six phases over the ETS blackboard under
link:lib/neural/coordinator.ex[], which calls the GNN, VAE and sequence
GenServers at lines 792, 865 and 869. All are plain Elixir (no Nx in
link:mix.exs[]). In link:lib/pattern_analyzer.ex[] the result can only
lower a recipe's confidence (`min/2`) or demote the finding.

Caveat::
PageRank convergence and the echo-state property are `open` ledger rows.
A comment in `pattern_analyzer.ex` still says "all 5 networks".

=== Bayesian confidence and outcome feedback

[quote, README.adoc]
____
*Bayesian confidence* — every recipe carries a Beta-distributed confidence updated from real
  outcomes, which gates whether a fix is applied automatically, proposed as a PR, or merely reported
____

[quote, README.adoc]
____
Outcomes flow back through
`mix hypatia.record_outcome`, which drives the Bayesian update and, when a recipe degrades,
auto-quarantine.
____

How this is implemented::
link:lib/outcome_tracker.ex[] lines 20–22 (prior strength 10, cap 0.99,
floor 0.10). Tiers 0.95 and 0.85 are in link:lib/triangle_router.ex[]
lines 24–25. `OutcomeTracker.quarantined?/2` (re-scan verification rate
below 0.30) downgrades `auto_execute` to review in
link:lib/fleet_dispatcher.ex[] line 267.

Caveat::
That recipe quarantine is not `Hypatia.Safety.Quarantine`, which nothing
calls (<<known-gaps>>). The Idris2 model of the update uses natural-number
pseudo-counts, not Elixir floats.

=== Machine-checked proofs

[quote, README.adoc]
____
*Machine-checked proofs* — Idris2 proofs of the ABI and the decision logic (confidence bounds,
  safety-triangle routing, dispatch thresholds, quarantine, rollback, the Bayesian update and rate
  limiting), one Agda model of the Logtalk-to-Elixir migration, and a TLA+
  model of the Kin gate that is model-checked on a bounded instance. The proofs are about models of
  the code, not the Elixir runtime itself. Proof ledger: 22 proven of 42; 0 proven-with-postulates,
  11 tested-only, 2 argued, 7 open
____

How this is implemented::
See <<proof-ledger>>. link:.github/workflows/verify-proofs.yml[] runs
`idris2 --check` per proof file, `idris2 --build` of both ipkgs, Agda in
its strict profile and TLC; Lean runs only for the HYP-01 control.

Caveat::
The Bayesian-update, rate-limiting, parser and neural-precondition proofs moved
from Lean to Idris2 on 2026-11-09, which removed the Lean kernel axioms
(`propext`, `Quot.sound`) four of them rested on.
The TLA+ row is `tested-only`: one bounded instance. The modelled rate
limiter is not called by any dispatch path. The census matches the ledger.

=== The safety triangle and novelty gating

[quote, README.adoc]
____
Every finding is routed *Eliminate > Substitute > Control*, in that order — remove the hazard
if you can, replace it if you cannot, and only then add a control around it.
____

[quote, README.adoc]
____
Unknown findings are forced to `report_only` regardless of score (novelty gating).
____

How this is implemented::
link:lib/pattern_analyzer.ex[] chains `VerisimConnector`, `PatternRegistry`
and `TriangleRouter`; link:lib/dispatch_manifest.ex[] writes
`pending.jsonl`. Eliminate dispatch passes the Kin gate
(link:lib/fleet_dispatcher.ex[] lines 235, 972–983). A novel finding goes to
Control in link:lib/neural/dispatch_guard.ex[] line 69.

Caveat::
The ordering is proved over models (`safety-triangle`, `abi-rule-engine`,
`dispatch-strategy`), not over the Elixir router. With the coordinator down,
an action is capped at review, not report-only (line 67).

=== Installation, usage and the operational surface

[quote, README.adoc]
____
`just --list` shows all 45 recipes; link:.github/CONTRIBUTING.md[`CONTRIBUTING.md`] treats `just` as the canonical entry point.
____

[quote, README.adoc]
____
Running the supervision tree also serves an HTML dashboard, an SSE event stream, a Prometheus
`/metrics` endpoint and an `/api/*` on port 9090. With
`HYPATIA_API_BEARER_TOKEN` set and not empty, every `/api/*` request needs that bearer
token. Without one, only loopback clients are answered unless
`HYPATIA_API_ALLOW_NONLOCAL=true`.
____

How this is implemented::
link:Justfile[] (with `contractile.just`), link:lib/hypatia/cli.ex[],
link:lib/mix/tasks/[]; link:mise.toml[] pins Erlang 27.3.4.4 and Elixir
1.17.3. link:lib/application.ex[] supervises 24 children (two more when
configured); link:lib/hypatia/web/router.ex[] serves `/`, `/metrics`, `/api`,
and `protect/2` in link:lib/hypatia/web/api_router.ex[] applies the bearer
and loopback policy. The recipe count is `just --summary | wc -w`; the six
CLI commands and the sixteen Mix tasks the README describes are gated as well.

Caveat::
`just build-all` builds the Rust workspace and Elixir; the README lists
`just build-ffi` and `just compile-abi` beside it for the Zig FFI and the
Idris2 ABI. No `guix.scm` is tracked: the README and AFFIRMATION say so, and
name `mise.toml` and `deploy/Containerfile` as the stand-ins.

[[known-gaps]]
== Known gaps

[CAUTION]
====
Safety systems are built but not wired. `Safety.RateLimiter` and
`Safety.Quarantine` have no caller in `lib/`. `BatchRollback.rollback/2` is
reached only through `Kin.Contingency.rollback_wave/2`, which nothing calls.
`SelfDiagnostics.record_dispatch_failure/0` and `record_dispatch_success/0`
have no callers, so its circuit breaker never opens. The moduledoc of
`lib/fleet_dispatcher.ex` (line 47) still names the rate limiter.
====

[CAUTION]
====
Learned patterns are not distilled into rules: the promotion and
recipe-generation code is never invoked. The README now presents the loop as
the design and says the rules are hand-written. No `guix.scm` is tracked.
Excluded `:verisim_data` tests run in no workflow (debt register T-1).
====
