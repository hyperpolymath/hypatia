= Credential roles and non-mutating validation
:revdate: 2026-11-07

`HYPATIA_SCAN_PAT` supplies read-only Contents and Dependabot-alert access for
the intended repository selection. The remediation sweep's query uses this
credential. Its later repository-dispatch step still uses
`HYPATIA_DISPATCH_PAT`; the two values are not fallbacks for one another.

Run the manual `Credential read check` workflow after replacing either secret.
Its separate jobs check authentication and one specific read endpoint without
checking out source, executing scanners, publishing findings, creating refs or
dispatching work. API bodies and secret values are not printed. An error is a
failed check, not an empty successful scan. Its summary explicitly limits the
claim: read success does not establish write access or complete estate coverage.

A PAT's display name is not linked to an Actions secret. Regeneration or
replacement requires updating each intended secret store with the new value.
Do not revoke the old PAT until all known consumers are migrated or explicitly
stopped. Do not paste credential values in issues, logs, source or chat.

The dispatch token is not a general administration credential. CI-health's
policy and workflow writes need a separately reviewed permission allocation;
successful authentication does not discharge that pending work. Likewise,
observation publication requires a qualified receipt in addition to access.
