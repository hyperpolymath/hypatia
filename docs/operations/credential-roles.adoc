= Credential roles and bounded validation
:revdate: 2026-11-16

`HYPATIA_SCAN_PAT` supplies read-only Contents, Dependabot alerts, Code scanning
alerts and Secret scanning alerts access for the intended repository selection.
Metadata read is automatic; no write or account permissions are needed for
these reads. The remediation sweep's query uses this
credential. Its later repository-dispatch step uses a short-lived GitHub App
installation token minted from `HYPATIA_APP_ID` and `HYPATIA_APP_PRIVATE_KEY`
(Contents: write on `gitbot-fleet` only; the App must be installed on both
`gitbot-fleet` and `verisimdb-data`, the latter for the credential read check); the PAT and the App are not
fallbacks for one another. `HYPATIA_DISPATCH_PAT` has been retired.

Run the manual `Credential read check` workflow after replacing either secret.
Its separate jobs check authentication and specific read endpoints without
checking out source, executing scanners, publishing findings, creating refs or
dispatching work. API bodies and secret values are not printed. An error is a
failed check, not an empty successful scan. Its summary explicitly limits the
claim: read success does not establish write access or complete estate coverage.

The scanner job requests one page of at most one alert from each of Hypatia's
Dependabot, code-scanning and secret-scanning endpoints. It suppresses all API
bodies and also requests `hide_secret=true` for secret scanning. Each endpoint
gets a separate summary result. Any failed or unavailable endpoint fails the
job, even when the other reads work. The dispatch job checks only identity and
observation-store visibility; it does not test a dispatch or write.

The fine-grained scanner token's resource owner is `hyperpolymath`. Selecting
all repositories covers that owner's repositories; it does not grant security
alert access under another owner such as `metadatastician`. A passing check
here tests only this repository's stored secret and these three endpoints.
The separate secret stored in `gitbot-fleet` needs its own validation.

The same workflow supports `workflow_call` so a consumer can validate its own
stored scanner credential without copying the check or handing the token to
an operator. Pin the reusable to a reviewed full commit SHA and pass only
`HYPATIA_SCAN_PAT`, never `secrets: inherit`. Reusable calls default to
`scanner_only: true`; the dispatch job is skipped and its secret is optional.
Manual runs default to checking both roles, with a `scanner_only` checkbox
for scanner-only validation. A caller that explicitly checks dispatch must
also pass `HYPATIA_APP_ID` and `HYPATIA_APP_PRIVATE_KEY`.

The API targets remain fixed: Hypatia's three alert endpoints and, only for
dispatch validation, the observation-store main ref. A successful call from
another repository proves that caller's stored scanner credential can read
those Hypatia endpoints. It does not prove access to every caller repository
or every estate repository.

A PAT's display name is not linked to an Actions secret. Regeneration or
replacement requires updating each intended secret store with the new value.
Do not revoke the old PAT until all known consumers are migrated or explicitly
stopped. Do not paste credential values in issues, logs, source or chat.

The dispatch token is not a general administration credential. CI-health's
policy and workflow writes need a separately reviewed permission allocation;
successful authentication does not discharge that pending work. Likewise,
observation publication requires a qualified receipt in addition to access.

== Observation-store publisher

`estate-rescan.yml` uses `VERISIMDB_DATA_PUBLISH_PAT` only in its preflight
and publication jobs. The scanner job has no publisher credential. There is
no fallback to the GitHub App credentials or `HYPATIA_SCAN_PAT`.

Provision a fine-grained token with resource owner `hyperpolymath`, only
`verisimdb-data` selected, Contents read/write and Pull requests read/write;
Metadata read is automatic. No Actions, Administration, Workflows or security
alert grants are needed for this publisher. Store its value in the
`VERISIMDB_DATA_PUBLISH_PAT` Actions secret of `hyperpolymath/hypatia`.
Do not install it in fleet or the private farm as part of this cutover.

For a bounded live check, manually run `Hypatia Estate Rescan` with
`credential_check_only=true` and `dry_run=false`. Only preflight runs: it
authenticates, reads the store main ref, creates a run-specific probe branch
at that existing commit and deletes it. It creates no commit, runs no scan,
opens no PR and publishes no observations. `dry_run=true` together with the
credential check is rejected before any API request; it is not a successful
write check. A failed probe deletion fails the job and needs investigation.

The probe proves authentication and branch creation/deletion, not PR creation,
merge eligibility, ruleset compliance or end-to-end publication. Ordinary
publication retains its existing two-PR flow and branch-policy checks.
Replacing this store role does not repair the separate fleet-dispatch or
CI-policy-administration roles.
