== Goal

`scripts/dispatch-runner.sh` gives its predicate verdict to
`mix hypatia.record_outcome --verdict`. The call for `no_op` and `unverified`
is no longer skipped. The automation quarantine does not change.

== Authority

* https://github.com/hyperpolymath/gitbot-fleet/issues/647[gitbot-fleet issue 647].
* https://github.com/hyperpolymath/hypatia/issues/984[hypatia issue 984], acceptance A3 and A5.

== Facts measured

gitbot-fleet commit `7fc2778`, read on 2026-11-14.

* `scripts/dispatch-runner.sh` exits with code 78 at line 152, before it reads
  the manifest. Nothing in this work order runs in production while that holds.
* `hypatia_record_outcome()` (line 222) calls `mix hypatia.record_outcome` with
  `--recipe`, `--repo`, `--file` and `--outcome` (line 255).
* The verdict is collapsed first (lines 336 to 357): `verified` gives `success`,
  `failed` and `incomplete` give `failure`, a refusal gives `false_positive`.
  `no_op` and `unverified` make no call.
* `tests/outcome-verdict-test.sh` tests the verdict library. `e2e.yml` runs it.
* hypatia commit `4d7f059`, `lib/mix/tasks/hypatia.record_outcome.ex` (line 59):
  the task ignores an option that it does not know. So a Hypatia from before
  `E0-01` gives exit code 0 for a call with `--verdict`, and it runs its old
  rescan for that call.
* Ran in hypatia: `mix help hypatia.record_outcome` prints the options of the
  task and writes nothing.

== Steps

. Confirm that `E0-01` is merged in hypatia. Stop if it is not.
. Measure the facts again.
. Learn once for each run whether Hypatia knows the option:
  `mix help hypatia.record_outcome` names `--verdict` only when it does. Do
  not learn it from an exit code. An older Hypatia ignores the option, so a
  `no_op` call could be recorded as a success.
  If the help command itself fails (an exit code that is not 0), stop the
  run with a visible error. A Hypatia that does not answer is not an older
  Hypatia, and the legacy call is for an older Hypatia only.
. When Hypatia knows the option: add the verdict as one more argument of
  `hypatia_record_outcome()` and pass `--verdict "$verdict"` for each of the 5
  verdicts. Use the `--outcome` value of the pair table of `E0-01`: `success`
  for `no_op` and `unverified`.
. When Hypatia does not know the option: keep the behaviour of today exactly.
  Pass no `--verdict`, and make no call for `no_op` and `unverified`.
. Log one line for each run that says which of the 2 modes it uses.
. Extend `tests/outcome-verdict-test.sh` with a stub `mix` on `PATH` that
  records its arguments. The stub answers `help hypatia.record_outcome` with
  or without `--verdict`, as the test case needs.

== Acceptance

* `bash tests/outcome-verdict-test.sh` passes. With a stub that knows the
  option, it shows the `--verdict` argument for each of the 5 verdicts. With
  a stub that does not, it shows no `--verdict` in any call and no call for
  `no_op` and `unverified`.
* `bash tests/automation-quarantine-test.sh` passes with no change to that file.
* `scripts/dispatch-runner.sh` still exits with code 78 before the manifest.
* The licence refusal gate in `scripts/dispatch-runner.sh` has no change.

== Stop and ask

* The interface of `E0-01` differs from this work order.
* The cost reaches the cap before the acceptance checks pass.
