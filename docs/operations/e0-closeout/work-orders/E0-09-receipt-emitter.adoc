== Goal

Hypatia writes one receipt for each learning update, in the form that the
ruled design of `E0-08` defines. A Nickel contract refuses a receipt that
claims more than its evidence.

== Authority

https://github.com/hyperpolymath/hypatia/issues/984[Issue 984], step 10 and
acceptance A7. The owner's rulings on the packet of `E0-08`.

== Facts measured

Commit `4d7f059`, read on 2026-11-14.

* No receipt emitter exists for the learning path (see `E0-08`).
* `schema/findings.ncl` is the model for a contract with a derived field. Its
  `LevelDerived` contract refuses a stored level that disagrees.
* `lib/hypatia/verdict.ex` annotates each finding in one place
  (`lib/hypatia/cli.ex`, line 1175: "Same funnel, exactly once").
* The qualified learning updates start in 3 places: `lib/outcome_tracker.ex`
  (`update_confidence_file/5`, line 420), the fleet import of
  `lib/learning_scheduler.ex` (`import_fleet_lines/2`), and the neural path of
  `lib/fleet_dispatcher.ex` (`ingest_fix_outcome/1` calls
  `Neural.Coordinator.record_outcome/3` through `record_neural_outcome/3`).
  `E0-05` makes the neural path learn from qualified outcomes only.
* `lib/outcome_tracker.ex`, `persist_outcome/6` (line 116): the outcome log
  is the commit point. The annealing state and the recipe summary are derived
  after it, and a failed derived write is retried from the log.

== Steps

. Confirm that `docs/design/e0-receipt.adoc` is merged and that its status is
  no longer `PROPOSED`. Stop if the owner has not ruled.
. Measure the facts again.
. Write `schema/receipt.ncl` from the field table of the design.
. Write the tests first: one receipt for one verified update, a filled
  `missing_evidence` for an update with a gap, and a refusal by the contract
  for a receipt with `qualification` "verified" and no evidence reference.
. Write `lib/hypatia/receipt.ex`: build, encode in canonical form, append.
  Call it from one place for each of the 3 learning paths.
. Follow the failure rule of the design for the order of the update and its
  receipt. Write a test for each failure point: the receipt write fails, and
  the update write fails. In each test, the failure is loud, and after the
  next run each update has exactly 1 receipt and no receipt is without its update.
. Add a test that the encoded line is byte-identical to a committed fixture.

== Acceptance

* `mix test` has 0 failures. The new tests are in `test/receipt_test.exs`.
* A verified update on each of the 3 learning paths writes 1 receipt (3 tests).
* A replay of the same event writes no second receipt (test).
* The 2 failure tests of step 6 pass.
* The fixture line is in canonical form: `jq -cS . fixture` prints the same
  bytes. This is the profile of `scripts/proof-ledger.sh` (ASCII strings, no
  numbers). If the design needs numbers, use the estate JCS tool and say so.
* No file that was formatted before the change is unformatted after it.
* The diff touches only `schema/`, `lib/hypatia/receipt.ex`, the 3 call sites and test files.

== Stop and ask

* The design is not ruled, or a field of the design cannot be filled as the
  design says.
* The design gives no failure rule, or `E0-05` is not merged.
* The canonical form needs a tool that the repository does not have.
* The cost reaches the cap before the acceptance checks pass.
