== Goal

`scripts/dispatch-runner.sh` gives each fix attempt one `event_id` before the
fix runs, and writes it to each outcome row of that attempt. The automation
quarantine does not change.

== Authority

https://github.com/hyperpolymath/hypatia/issues/984[hypatia issue 984], step 6:
"append an identifiable attempt_id with stable producer identity and source
event provenance before execution". The id format is the one that the owner
rules on in the packet of `E0-08`.

== Facts measured

gitbot-fleet commit `7fc2778`, read on 2026-11-14.

* `scripts/dispatch-runner.sh`, `record_outcome()` (line 283) writes these
  fields: `pattern_id`, `recipe_id`, `repo`, `file`, `outcome`, `verdict`,
  `exit_code`, `before_hits`, `after_hits`, `timestamp`, `bot`. It writes no id.
* The script exits with code 78 at line 152, before it reads the manifest.
* The estate rule for a new identifier is ADR-008. A random version 4 UUID
  from `uuidgen` does not meet it.

== Steps

. Confirm the ruled id format of `E0-08` and that `E0-11` is merged. Stop if not.
. Measure the facts again.
. Mint the id once for each attempt, before the fix script starts. Use the
  estate tool that the ruling names. Do not write a new id generator in shell.
. Write the id as `event_id` in each row of the attempt, in both outcome logs.
  Build the JSON with `jq`.
. Extend `tests/outcome-verdict-test.sh`: 2 attempts with the same input give
  2 different ids, and all rows of 1 attempt carry the same id.

== Acceptance

* `bash tests/outcome-verdict-test.sh` and `bash tests/automation-quarantine-test.sh` pass.
* A row from the test passes the import tests of `E0-11` (run them in a
  hypatia checkout and give the output).
* `scripts/dispatch-runner.sh` still exits with code 78 before the manifest.
* The licence refusal gate has no change.

== Stop and ask

* The ruling names no tool that can mint the id in this repository.
* Any step needs a change to the quarantine.
* The cost reaches the cap before the acceptance checks pass.
