== Goal

The neural coordinator trains on a fix outcome only when the outcome is
qualified. An unqualified outcome is logged and is not learned.

== Authority

https://github.com/hyperpolymath/hypatia/issues/984[Issue 984], step 9
("Bayesian counts, annealing, cross-repo transfer and dispatch decisions use
the same verified-evidence qualification") and acceptance A3.

== Facts measured

Commit `4d7f059`, read on 2026-11-14.

* `lib/fleet_dispatcher.ex`, `ingest_fix_outcome/1` (about line 714): it reads
  the boolean `:success` from the finding, builds `"success"` or `"failure"`
  (line 726) and calls `record_neural_outcome/3` (line 728).
* Same file, `record_neural_outcome/3` (line 691) calls
  `Hypatia.Neural.Coordinator.record_outcome/3`.
* `lib/neural/coordinator.ex`, `record_outcome/3` (line 386): the handler
  trains the Mixture of Experts and feeds the Liquid State Machine (about
  lines 654 to 661).
* The offline paths already qualify: `lib/neural/training_pipeline.ex` (line 97),
  `lib/neural/rebalancer.ex` (line 260), `lib/neural/graph_of_trust.ex` (line 77).
* No test covers the path from `ingest_fix_outcome/1` to the coordinator.

== Steps

. Measure the facts again. Stop if one no longer holds.
. Write the tests first. Use a fake coordinator process that records what it receives.
. In `ingest_fix_outcome/1`, build the same map shape that
  `OutcomeTracker.qualified_outcome?/1` reads. Call the coordinator only when
  that function returns `true`.
. For an unqualified outcome, log one line at `info` level with the pattern and
  the repo. Do not call the coordinator.
. Do not change `Coordinator.record_outcome/3`.

== Acceptance

* New tests show:
** a finding with `success: true` and no verification does not reach the coordinator;
** a finding with a verified success reaches it once;
** a finding with a qualified failure reaches it once.
* `mix test test/neural_training_qualification_test.exs test/graph_of_trust_qualification_test.exs`
  passes. `mix test` has 0 failures. No file that was formatted before the change is unformatted after it.
* The change touches only `lib/fleet_dispatcher.ex` and test files.

== Stop and ask

* The finding has no field that carries the verification. Then the producer
  of the finding must change, and that is a larger work order.
* A test needs a change in `lib/neural/coordinator.ex`.
* The cost reaches the cap before the acceptance checks pass.
