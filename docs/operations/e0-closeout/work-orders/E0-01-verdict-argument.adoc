== Goal

`mix hypatia.record_outcome` accepts a `--verdict` option with the 5 values
that the fleet computes. Hypatia stores the verdict in the outcome row. A
verdict can lower trust. It can never raise trust by itself.

== Authority

* https://github.com/hyperpolymath/gitbot-fleet/issues/647[gitbot-fleet issue 647]:
  only `verified` is positive evidence, `no_op` is neutral, `unverified` is no evidence.
* https://github.com/hyperpolymath/hypatia/issues/984[Issue 984], acceptance A3.

== Facts measured

Commit `4d7f059`, read on 2026-11-14.

* `lib/mix/tasks/hypatia.record_outcome.ex`, `run/1` (line 58): the switches
  (line 45) have no verdict. `--outcome` accepts `success`, `failure` and
  `false_positive` only (lines 68 to 82).
* Same function: it reads the options with `OptionParser.parse/2` and drops
  the list of invalid options (line 59: `{opts, _, _}`). An option that the
  task does not know is ignored with no error.
* Same function: with `--no-verify` the row gets `"verification" => "unverified"`
  (line 112). Without it, `OutcomeTracker.record_outcome_for_fix/5` rescans.
* `lib/outcome_tracker.ex`, `record_outcome_for_fix/5` (line 258) and
  `record_and_verify/5` (line 320) write each row with a fixed metadata map.
  They accept no other row field.
* `lib/outcome_tracker.ex`, `qualified_outcome_counts/1` (line 486): a success
  row counts only with `"verification" => "verified"`. A failure row counts
  with `failed`, `incomplete` or `verified`. Every other row is `ignored`.
* gitbot-fleet commit `7fc2778`, `scripts/dispatch-runner.sh` (lines 342 to
  357): the runner calls this task with `success` for `verified`, and with
  `failure` for `failed` and `incomplete`. It makes no call for `no_op` and
  `unverified`.
* Same commit, `scripts/lib/outcome-verdict.sh`, `legacy_outcome`: the outcome
  that the fleet writes beside a `no_op` or `unverified` verdict is `success`.
  It reports the exit status only.
* Ran: `mix help hypatia.record_outcome` prints the options of the task.
* No test in `test/` runs this Mix task.

== Steps

. Measure the facts again. Stop if one no longer holds.
. Write the tests first, in a new file `test/mix_tasks/record_outcome_test.exs`.
  Use a temporary data directory. Do not write to a real outcome log.
. Add `verdict: :string` to the switches. Accept `verified`, `no_op`,
  `incomplete`, `unverified` and `failed`. Reject any other value with exit code 1.
. Stop with exit code 1 and a clear message when the command line has an
  option that the task does not know. Today the task ignores it.
. Accept only the pairs of this table. Reject each other pair, and
  `--outcome false_positive` with any verdict, with exit code 1 and a clear
  message. Write no row for a rejected call.
+
[cols="1,1,3",options="header"]
|===
|`--verdict` |`--outcome` |Behaviour
|`verified` |`success` |No change from today. The rescan of Hypatia decides `"verification"`.
|`no_op` |`success` |No rescan. Record with `"verification" => "no_op"`.
|`unverified` |`success` |No rescan. Record with `"verification" => "unverified"`.
|`incomplete` |`failure` |Record the failure with `"verification" => "incomplete"`.
|`failed` |`failure` |Record the failure with `"verification" => "failed"`.
|===
. Store the verdict as `"verdict"` in each row that the call writes. The
  rescan path cannot do that today. Give `record_and_verify/5` an option
  `:metadata` (a map) that it merges into each row that it writes. A key that
  the function sets itself wins over the map.
. Add the verdict to the `--format json` output.
. Name `--verdict` and the pair table in the `@moduledoc` of the task. The
  fleet reads `mix help hypatia.record_outcome` to learn whether the option
  exists (`E0-02`).
. Add the option to `docs/operations/dispatch-runner-contract.adoc`.

== Acceptance

* `mix test test/mix_tasks/record_outcome_test.exs` passes. The tests show:
** a `no_op` row and an `unverified` row leave `qualified_outcome_counts/1` at
   zero successes and zero failures;
** a `failed` row and an `incomplete` row count as 1 failure each;
** an invalid verdict, a pair that the table does not list and an unknown
   option exit with code 1 and write no row;
** a call with `--verdict verified` writes `"verdict" => "verified"` in each
   row, whatever the rescan returns;
** a call with no `--verdict` behaves as before and writes no `"verdict"` key.
* `mix help hypatia.record_outcome` names `--verdict`.
* No file that was formatted before the change is unformatted after it. `mix test` has 0 failures.
* The change touches only the Mix task, `lib/outcome_tracker.ex` (the
  `:metadata` option), their test files and the contract document.
