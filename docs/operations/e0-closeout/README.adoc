== What this folder is

This folder holds the work orders that close step E0 of
https://github.com/hyperpolymath/hypatia/issues/984[issue 984] ("Event chain
E0-E5"). E0 is the Hypatia part of Wave 0, item 1 ("true outcomes"), of the
Kautz-ladder ultraplan
(`docs/ULTRAPLAN-KAUTZ-LADDER-2026-10-19.adoc` in `metadatastician/standards`).

The owner chose "E0 close-out" as the first target on 2026-11-14. Each work
order is one bounded task for one agent run. One work order makes one branch
and one draft pull request.

Nothing here is a claim that E0 is done. E0 is done only when work order
`E0-16` writes its acceptance receipt and the owner accepts it.

== Baseline, measured 2026-11-14

Measured at `main` commit `4d7f059` with Erlang/OTP 27.3.4.19 and Elixir 1.17.3.

* `mix test`: 3,145 tests, 0 failures, 246 excluded, 54 seconds.
* The 4 test files that the E0 step of `tests.yml` names (`outcome_tracker_test`,
  `cross_repo_learning_test`, `outcome_tracker_runtime_store_test`,
  `learning_runtime_store_test`): 61 tests, 0 failures.
* `learning_scheduler_test`, `neural_training_qualification_test`,
  `graph_of_trust_qualification_test`, `retraction_test`: 51 tests, 0 failures.
  No targeted step names these 4 files. The `Integration Tests` job runs the
  whole suite (`mix test --include integration`), so they do run in CI.
* The comment in `.github/workflows/tests.yml` that says the repository has
  "known-red test families" did not match this run.
* `mix format --check-formatted` reported 25 unformatted files, and no CI job
  runs it. So the rule for a work order is narrower: a file that was formatted
  before the change stays formatted. An agent does not reformat a file that
  was not. It writes its new lines in the style of the file.
* The suite wrote 71 test rows into the tracked outcome file of a sibling
  `gitbot-fleet` checkout. `config/test.exs` does not move the fleet path to
  the test store. `E0-17` corrects that.
* The fleet writes `"outcome": "success"` beside the verdict `incomplete`, and
  the import accepts `incomplete` only with `failure`. So the import drops
  that negative evidence. `E0-03` corrects that.

A line number in a work order is correct for commit `4d7f059` only. The
function name is the stable locator. Measure again before you edit.

== Rules for every run

* One work order, one branch, one draft pull request. The agent never merges.
* The agent reads the work order, then measures the facts again. A fact that
  no longer holds stops the run.
* The agent stops and asks at each condition under "Stop and ask". It does not
  invent a design answer.
* The pull request body follows `templates/pr-body.adoc`. It has an "Evidence"
  part, a "Not done" part and a "Cost" line.
* No run edits a licence file, an SPDX header, or `.github/workflows/actions.lock`.
* A run leaves no change in another repository. Until `E0-17` merges,
  `mix test` adds test rows to a sibling `gitbot-fleet` checkout. Run
  `git -C ../gitbot-fleet status --short` after the suite and report a change
  in the pull request body. Do not restore that file yourself: it can hold
  real rows that are not committed yet. The test rows have
  `"bot": "hypatia"` and the repo `r` or `test-repo`.
* A model above the tier in the work order needs a reason in the pull request body.
