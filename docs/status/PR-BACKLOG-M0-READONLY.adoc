= M0 read-only PR backlog census
:toc:

== Scope

This is the discovery-only entry point for Hypatia issue #1217. It is not an executor, a review scheduler, a PR disposition engine, or a replacement for `estate-stats.sh`. It does not call the gitbot-fleet dispatch runner or request paid reviews. It leaves the production fleet quarantine unchanged.

Run from an authenticated, explicitly authorised workstation or CI job with GitHub CLI (`gh`) and `jq` available:

[source,sh]
----
./scripts/sweeps/estate-pr-census-readonly.sh --out-dir /tmp/hypatia-pr-inventory
bash tests/estate-pr-census-readonly-test.sh
----

`--org OWNER` may be repeated to narrow the scope. The default owners are `hyperpolymath`, `catachresis-colloquium`, `metadatastician`, and `stuff-of-awe`. No GitHub repository is written to: the only GitHub operation is `gh api --method GET`. Local output is two files, `pr-inventory.jsonl` and `pr-census.json`.

== Verification contract

* Reject API failures, inconsistent `total_count`, `incomplete_results`, malformed required fields, duplicate identities, wrong owner, and the 1,000-result search ceiling.
* Require all expected rows before replacing the local output pair. This is not a multi-file atomic transaction: a consumer must verify the summary's `complete_first_pass` marker *and* row count, and avoid stale files from earlier runs if a new run fails. Prefer a fresh directory per run until a versioned publication mechanism exists.
* Search pagination is not an atomic snapshot even when counts match. Moving PRs may escape or repeat between pages; repeated samples or an immutable reconciliation pass are needed before treating this as a dispatch input.
* Unknown means *unmeasured*. No head SHA, required-check decision, reviewer success, merge safety, or policy permission is inferred. A missing draft field remains unknown, never false.
* `pr-census.json` describes coverage of the authorised, searchable account set, not every repo the owner could theoretically access.
* Outputs are provisional reporting JSON, not canonical I-JSON/JCS evidence receipts and never authorise mutations.

== Relationship to established tooling

`estate-stats.sh` remains the dashboard producer, with its current schema and PR disposition contract unchanged. It consumes a separately generated `pr-decisions.jsonl`; this first-pass inventory does not produce dispositions. A future versioned adapter may add an explicitly identified *inventory* section or separate dashboard feed, rather than silently substituting an inventory count for policy decisions. `Hypatia.ReviewGithubCollector` in PR #1216 gathers evidence for **one** PR; this sweep only enumerates PR identities and basic search metadata.

No action may raise confidence, classify a PR as merge-ready, dispatch fixes, modify policy, or lift fleet quarantine on these outputs. After this discovery stage, planned milestones are current-head and check/review enrichment, independent observations, pinned format validation via ijson-jcs, and canary evidence receipts.

== Local verification (23 November 2026)

The dedicated shell test was exercised locally against mocked GET-only responses: valid responses, missing draft metadata, incomplete results, duplicate identities, missing author, wrong owner, search cap, network failure, zero results, and shell syntax. Those tests are not evidence of a live `gh` canary on this exact branch. The independent connected GitHub census previously retrieved 565 open PRs across 271 repositories, but was not generated by this script.

== M0-D bounded, non-authorising PR enrichment

The second read-only stage is +scripts/sweeps/estate-pr-enrich-readonly.sh+.
It takes a completed M0 inventory and uses only authenticated GitHub REST GET
calls. The default is a ten-PR canary; it must not fan out to the estate by
accident. To inspect a narrower target, give a repository and PR number.

[source,sh]
----
bash scripts/sweeps/estate-pr-census-readonly.sh --out-dir /tmp/hypatia-census-001 --org hyperpolymath
bash scripts/sweeps/estate-pr-enrich-readonly.sh \
  --inventory-dir /tmp/hypatia-census-001 \
  --out-dir /tmp/hypatia-enrichment-001 \
  --limit 10
# Narrower read-only canary; each run requires a fresh output directory:
bash scripts/sweeps/estate-pr-enrich-readonly.sh \
  --inventory-dir /tmp/hypatia-census-001 \
  --out-dir /tmp/hypatia-enrichment-002 \
  --repo hyperpolymath/hypatia --number 1216
bash tests/estate-pr-enrich-readonly-test.sh
----

The output files are +pr-enrichment.jsonl+ and +pr-enrichment-summary.json+.
For each selected PR, the collector reads the PR twice and checks that the head
SHA remained stable. Between those reads it retrieves check runs with all
pages, review submissions with all pages, and the combined commit status. If a
GET fails or a list is truncated/duplicated, the relevant subsource is
*unavailable*, not empty or clean. If the head changes, the result is
+head_changed_or_unverified+, never a current verdict.

The collector does *not* interpret branch protection, rulesets, required-check
contexts, effective reviewer approvals, source attestations or policy grants.
It reports +required_checks+ and +merge_eligibility+ as +unmeasured+ regardless
of check outcomes. Even a green set of observed checks is not merge authority.
Review submissions are observations, not proof that a reviewer completed a
substantive run. These JSON outputs are provisional, not JCS-canonical signed
receipts or verified repair outcomes.

No API mutation, merge, review request, code execution, new dependency, or
gitbot-fleet quarantine change is part of M0-D. Do not run the enrichment
against all 565 identities without a fresh bounded scope and API budget.

The offline regression test includes 101 check runs across two pages,
head drift between observations, failed check API access, stale output and
incomplete input inventory. The script itself has *not* been run live through
GitHub CLI on this branch. Independently, a connected GitHub API read of
Hypatia PR #1216 observed a stable head, 113 checks across 100+13 entries,
nine review submissions, three failed checks and a failing combined status
(23 November 2026). This validates the need for pagination, not the script
runtime.

== Integration hold points

. Run live `gh` canary on a narrowly scoped owner, comparing GitHub search identities against an independent read.
. Qualify the M0-D enrichment implementation with a live bounded GitHub CLI canary. The read-only implementation and offline tests now exist; required-check policy and attested review coverage remain unmeasured.
. Introduce canonical evidence/receipt persistence with the pinned I-JSON/JCS tooling, explicitly preserving JSONL framing and all unknowns.
. Integrate a versioned census feed into the existing estate stats/dashboard rather than modifying its existing disposition semantics.
. Open a draft PR only when desired; creating a PR may itself trigger external code-review billing. Keep repair and merge gates off until separately qualified.
